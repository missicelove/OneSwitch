# PeerLink — implementation spec

Class PeerLinkModule: FeatureModule, PeerHub — "public init()" must keep working for the app; add an internal/public designated initializer that injects configuration for tests (UserDefaults/SettingsStore suite, deviceID, passcode, port, Bonjour service type override such as "_oneswitch-test._tcp", interface policy) so TWO hubs can run in one process. id "peerlink", displayName "雷雳互联", symbolName "cable.connector". Implement the PeerHub / PeerChannel contract in Sources/OneSwitchCore/PeerAPI.swift EXACTLY (buffer until setHandlers, onClose exactly once after the last message, completion-based send, one channel per service, replacement closes the old channel first, reserved types 0xFF00…0xFFFF never surfaced to services, payload limit).

IDENTITY & PAIRING
- localDeviceID: random UUID persisted in settings. localDeviceName: Host.current().localizedName.
- 配对码 (passcode): identical string entered on both Macs. Settings: SecureField + show toggle + "生成随机配对码" (8 chars, unambiguous alphabet) + copy button. No passcode → status .disabled(reason: "请先设置配对码"). No registered services → .disabled(reason: "未启用文件同步或键鼠共享").

TRANSPORT (Network.framework)
- One NWListener (TCP) on a fixed port (default 52525, configurable; if busy fall back to an OS-assigned port) advertising Bonjour "_oneswitch._tcp" (instance name = device name, TXT: id=<deviceID>, v=1, port). One NWBrowser for the same type (with bonjourWithTXTRecord descriptor); ignore our own id.
- Security: TLS 1.2 PSK like Apple's TicTacToe Network.framework sample: PSK = HMAC-SHA256(key: SymmetricKey(passcode utf8), data: "OneSwitch-PSK-v1"), identity "OneSwitch", sec_protocol_options_add_pre_shared_key + sec_protocol_options_append_tls_ciphersuite(TLS_PSK_WITH_AES_128_GCM_SHA256). VERIFY with a real loopback test that it works on macOS 27. If TLS-PSK is unusable, fall back to plain TCP + mutual HMAC challenge-response + per-frame ChaChaPoly (CryptoKit) with HKDF-derived session keys. A wrong passcode must produce status .error("配对码不匹配：请确认两台 Mac 的配对码一致") and no channel.
- TCP options: noDelay = true (critical: keyboard/mouse latency), enableKeepalive (idle 3 s, interval 1 s, count 3), connectionTimeout 5 s.
- Framing: [UInt32 BE payload length][UInt16 BE type][payload]. After connect: handshake hello {protocolVersion, deviceID, deviceName, service} → hello-ack or reject (service not registered / protocol mismatch). 5 s handshake timeout. Receive loop reads header then body (reject > PeerLimits.maxPayloadSize → close with protocolViolation).
- Heartbeat: reserved-type ping every 2 s per channel; close the channel (onClose with .timeout) if nothing is received for 6 s. Measure RTT for diagnostics.
- Dialing: for every registered service with no live channel, the side with the lexicographically smaller deviceID dials; the other side also dials if nothing arrived after ~4 s (asymmetric discovery). If duplicate channels for a service form, deterministically keep the one initiated by the smaller deviceID on both sides. Exponential backoff 1 s → 30 s, reset on success or path change. Respect the contract: a newer channel replaces an older one (close old first, then hand out the new one).
- Callbacks: onChannel handlers on the main actor; channel I/O on its own serial queue; onMessage on the queue given to setHandlers.

INTERFACE POLICY & THUNDERBOLT
- Setting "网络接口": 仅雷雳网桥 / 优先雷雳网桥 (default) / 任意网络. Find the Thunderbolt bridge via NWPathMonitor availableInterfaces (name hasPrefix "bridge") and getifaddrs; for thunderbolt-only set requiredInterface on listener/browser/connection parameters; for "prefer" dial through the bridge interface when the browse result lists it. PeerInfo.viaThunderbolt from the connection path's interface name; PeerInfo.address from the remote endpoint.
- Direct-address fallback: setting "对方 IP（可选）"; if unset but static-IP mode is on, derive the peer IP (.1 ⇄ .2). If Bonjour finds nothing within ~5 s, dial host:port directly (both ports 52525 by default).
- Local Network privacy (macOS 15+): Info.plist already has NSLocalNetworkUsageDescription + NSBonjourServices ["_oneswitch._tcp"]. Detect policy-denied errors (NWError .dns(kDNSServiceErr_PolicyDenied = -65570) etc.) → status .error("未获得“本地网络”权限：请在 系统设置 → 隐私与安全性 → 本地网络 中允许 OneSwitch").

AUTOMATIC IP CONFIGURATION (the user asked for "开机自启自动配置IP")
- Resolve the network service bound to the bridge device by parsing "networksetup -listnetworkserviceorder" ("(Hardware Port: Thunderbolt Bridge, Device: bridge0)") — the service name may be localized (e.g. "雷雳网桥"); never hardcode it. Read current config with "networksetup -getinfo <service>" and addresses via getifaddrs.
- Setting "自动配置雷雳网桥静态 IP" (default ON): subnet 10.77.0.0/24; this Mac = 10.77.0.1 on desktops, 10.77.0.2 on laptops (AppEnvironment.isLaptop), user-editable. At start() (and on "立即配置"), if the bridge service is not already manual with that IP, apply "networksetup -setmanual '<service>' <ip> 255.255.255.0" (no router, so no default route is created) through NSAppleScript "do shell script ... with administrator privileges" (the macOS password dialog; the user types the password). Quote arguments safely. If the user cancels, remember it and do not prompt again automatically until they press "立即配置". Also "恢复为自动（DHCP）" → "networksetup -setdhcp '<service>'". Configuration persists across reboots, so later launches only verify it. NEVER execute these commands during development/checks — unit-test the command builders and parsers only.
- Show bridge status: cable/link present (bridge has active members / an address), local IPs, peer IP, whether static config matches.
