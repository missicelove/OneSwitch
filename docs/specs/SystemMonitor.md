# SystemMonitor — implementation spec

Class SystemMonitorModule: FeatureModule, "public init()", id "monitor", displayName "系统监控", symbolName "gauge.with.dots.needle.33percent".

METRICS (samplers run on a background queue at a configurable interval 1/2/3/5 s, default 2 s; only sample what is displayed or while the detail popover/settings are visible)
- cpu: host_processor_info tick deltas → total %, user/system split; also P-core / E-core averages using sysctl hw.perflevel0.logicalcpu (P) / hw.perflevel1.logicalcpu (E) (on Apple Silicon the E-cores come first in the processor list — verify ordering; if unsure show total only).
- gpu: IOServiceMatching("IOAccelerator") → "PerformanceStatistics" → "Device Utilization %" (fallback "Renderer Utilization %"); also "In use system memory" if present.
- memory: host_statistics64(HOST_VM_INFO64): used = app memory (internal_page_count − purgeable_count) + wire_count + compressor_page_count, times page size (vm_kernel_page_size), over hw.memsize → %. Also swap used (sysctl vm.swapusage) and pressure level (kern.memorystatus_vm_pressure_level 1 normal / 2 warn / 4 critical → 正常/警告/严重).
- network: 64-bit counters via sysctl CTL_NET/PF_ROUTE/NET_RT_IFLIST2 (if_msghdr2 / if_data64). Sum interfaces that are up and carry an IPv4/IPv6 address (this counts bridge0 but not its member ports, avoiding double counting) excluding lo0, utun*, awdl*, llw*, anpi*, gif*, stf*, ap*. Rates ↑/↓ bytes/s. Keep a per-interface breakdown and label "bridge*" as "雷雳网桥", en0 "以太网"/"Wi‑Fi" via SCNetworkInterface or networksetup-free detection (SystemConfiguration SCNetworkInterfaceCopyAll → BSD name → localized display name). Setting: 全部接口 or a specific interface.
- disk: read/write rates from IOBlockStorageDriver "Statistics" ("Bytes (Read)", "Bytes (Write)") summed over physical drivers; plus capacity used % of the boot data volume (URLResourceValues volumeTotalCapacity / volumeAvailableCapacityForImportantUsage of "/").
- power: total system power in W from SMC key "PSTR" (Apple Silicon, type 'flt ' little-endian float); if missing try "PDTR"/"PPBR". On laptops also battery % / charging / adapter watts via IOPSCopyPowerSourcesInfo and AppleSmartBattery (Voltage × Amperage, "AdapterDetails" Watts). Optional extra: CPU/GPU/ANE power via IOReport ("Energy Model" channels) loaded with dlopen("/usr/lib/libIOReport.dylib") — only if it works reliably.
- temperature: Apple Silicon SMC — open AppleSMC (IOServiceGetMatchingService "AppleSMC", IOServiceOpen, IOConnectCallStructMethod selector 2 with the classic SMCKeyData_t struct: 80 bytes, commands readKeyInfo=9 / readBytes=5 / getKeyFromIndex=8, "#KEY" for the key count). Enumerate keys once (cache), read 'flt ' values: CPU = average (and max) of keys starting "Tp" or "Te" in 10…120 °C; GPU = keys starting "Tg". Fallback: private IOHIDEventSystemClient API (IOHIDEventSystemClientCreate, IOHIDEventSystemClientSetMatching with PrimaryUsagePage 0xff00 / PrimaryUsage 5, IOHIDServiceClientCopyEvent type 15, IOHIDEventGetFloatValue field 15<<16) declared with @_silgen_name or dlsym, averaging sensors whose Product name contains "tdie"/"PMU tdie". Probe on this M4 Max and print which keys/sensors you found and their values. SMC reads must never run on the main thread.

MENU-BAR DISPLAY
- Each metric can be shown as its own NSStatusItem ("单项"), any combination; option "合并为一个图标" shows all selected metrics in one item. Defaults: CPU + 内存 + 网络 on, others off.
- Create ALL metric items once in start() (fixed order, set isVisible from settings) — do not create items later at runtime, since the menu-bar hider module places its separator right after this module starts. New items appear to the LEFT of existing ones, so create them in reverse of the desired left-to-right order (desired left→right: CPU, GPU, 内存, 网络, 磁盘, 功率, 温度). autosaveName "OneSwitchMonitor.<metric>" + AppEnvironment.profileSuffix. The combined item is a separate item created the same way.
- Rendering: compact, stable-width text with monospaced digits so the bar does not jitter: small caption label + value (e.g. two-line "CPU" over "23%", or one line "CPU 23%"), network as two stacked lines "↑1.2M" / "↓34K", disk as "R 12M / W 3M" (or used %), power "38W", temperature "52°" . Style setting: 文字 / 图标+数值 (SF Symbols cpu, memorychip, network, internaldrive, bolt, thermometer.medium) / 迷你图 (sparkline image of the last 30 samples). Render to NSImage (template for monochrome) or NSAttributedString with NSFont.monospacedDigitSystemFont(ofSize: 9–10); verify it fits the menu-bar height (NSStatusBar.system.thickness).
- Optional colour warning (setting): CPU/内存 ≥ 85 % or temperature ≥ 90 °C tint the value orange/red.
- Clicking any monitor item opens an NSPopover (SwiftUI) with all metrics: current values, 60-sample sparklines (Canvas or Path), CPU P/E split, memory breakdown & pressure, per-interface network rates, disk R/W + capacity, power & temperatures (CPU/GPU), and the top 5 processes by CPU (run "/bin/ps -Aceo pid,pcpu,comm -r" off-main only while the popover is open). Buttons: 活动监视器, 设置….

MODULE UI
- Menu section: a compact summary line per enabled metric (info items, e.g. "CPU 23% · GPU 4% · 内存 61%", "网络 ↑1.2 MB/s ↓34 KB/s", "温度 CPU 48°C GPU 41°C", "功率 38 W"), and submenu "在菜单栏显示" with checkable metric items + "合并显示".
- Settings page: per-metric toggles (with live current value next to each), 显示样式, 刷新间隔, 网络接口, 温度来源 (CPU/GPU/最高), 合并显示, 高负载颜色提醒.

CHECKS: each sampler over 2 real samples on this Mac returns sane values (cpu/gpu/memory 0…100, network/disk counters non-decreasing, temps 10…120 °C when found, power 1…500 W when found) — print the values and which SMC keys / HID sensors were used; formatter/width tests for the status-item text; NET_RT_IFLIST2 parsing; sparkline buffer logic.
